# PRD｜企业知识问答的证据核验与规则一致性增强（提案 V1.0）

**产品性质：** 模拟企业内部知识问答助理的改进方案；仅依据本项目30条评测中的观察。  
**状态：** 提案，未开发、未上线、未经对照实验验证。

## 一、问题与目标

用户希望模型基于明确标注版本的员工制度回答报销、请假、培训问题。当前测试中的四条回答存在：规则跨域外推（TC007）、虚构引用章节（TC014）、条款适用范围扩大（TC025）、分项与总结不一致（TC028）。这些问题可能降低用户对制度回答的可核验性。

**目标：** 提高有依据答案的可核验性，阻止“看起来合理但未被文档支持”的结论，同时不牺牲必要信息覆盖率。

## 二、潜在用户需求

- 作为员工，我希望知道一个制度结论到底引用了哪个**有效版本**及哪个**具体章节**。
- 作为HR，我希望AI区分明确条件、未规定事项和未生效草案，不自造解释。
- 作为产品评测人员，我希望逐项判断与最终结论保持一致，并能复现失败案例。

## 三、拟议需求与验收条件

| 优先级 | 功能需求 | 验收方式（提案） | 对应案例 |
|---|---|---|---|
| P0 | 引用存在性校验：返回前校验文档ID、版本、章节确实存在于本次允许来源。 | 在独立保留集上虚构章节数为0；找不到时改为“无法验证引用”，不伪造来源。 | TC014 |
| P0 | 结论证据绑定：对每条关键制度结论标注对应证据范围，并识别“本条款没有规定”的情形。 | 对跨条款规则迁移专项测试，未经支持的确定性结论数下降；同时监控误拒答。 | TC007、TC025 |
| P1 | 条件结构化检查：按资格、额度、提前申请、审批等分项输出，并在最终结论前做一致性校验。 | 分项与总结不一致的数量在保留集上显著下降（描述性计数，样本扩大后再做统计检验）。 | TC028 |
| P1 | 版本与时间有效性过滤：不把历史版和草案当成当前执行标准。 | 不同日期/版本配对题均能引用正确的有效条款；未来制度不确定时明确说明。 | TC009—TC014 |
| P2 | 记录模型/知识库/提示词版本与Token用量。 | 每条调用都有来源哈希、模型、参数、时间戳、原始输出；认证信息从不写入日志。 | 全部 |

## 四、拟议工作流

1. 输入问题与查询日期，解析制度主题及关键条件。
2. 从允许的知识库获取条款，并标记**文档ID、版本、有效时间、章节**。（目前项目是全文注入；未来RAG部署才需要检索模块。）
3. 将每个拟输出的制度性结论与证据片段对齐；证据缺失则回答“无法确认”，而不补充通常惯例。
4. 检查引用章节真实存在、条款有效，分项检查结果与总结一致。
5. 输出回答、章节引用、无法确认的事项，并记录匿名化评测日志。

## 五、实验计划（尚未执行）

- **对照：** 当前Qwen非思考模式基线提示词；**实验组：** 仅增加证据绑定/引用存在性/一致性检查中的一个模块，避免一次同时更改多个变量。
- **数据：** 使用新的独立保留集，包含相同机制但不同金额、时间及条款的配对题；原30条可作为回归测试集但不能单独证明泛化改进。
- **指标：** Factual Correctness、Citation Correctness、Answer Completeness、Groundedness、误拒答率、Token用量、端到端延迟（后两项需实际记录）。
- **验收：** 优先消除引用伪造和未经支持的制度性结论；目标阈值以新保留集大小和风险容忍度重新定，不以30条样本承诺生产级准确率。

## 六、风险与边界

- 过度保守：对“最高报销500元”之类明确事实仍应清楚回答；不要把所有问题退回HR。
- 版本冲突：正式版、草案及历史版必须携带有效期；日期不明时回答应明确限定条件。
- 上线迁移：若系统用于真实政策，应经过业务规则负责人验证，不能直接复用虚构制度。
- 成本与性能：新增核验步骤可能增加延迟和Token，需通过A/B实验量化。
